Project · NetwerkbeveiligingProject · Network security

Het thuisnetwerk van mijn ouders beveiligen. Securing my parents' home network.

Een van mijn grootste leerscholen: van een standaard router van de provider naar een eigen firewall, versleuteld DNS-verkeer en veilige wachtwoorden voor het hele gezin. One of my biggest learning experiences: from a standard ISP router to my own firewall, encrypted DNS traffic and secure passwords for the whole family.

SituatieSituation
Een standaard router van de provider met een basisfirewall, en overal dezelfde, zwakke wachtwoorden.A standard ISP router with a basic firewall, and the same weak passwords everywhere.
DoelGoal
Het netwerk zo goed mogelijk beveiligen, zonder dat surfen, streamen of thuiswerken er hinder van ondervinden.Secure the network as well as possible, without getting in the way of browsing, streaming or working from home.
Wat ik deedWhat I did
  • Eigen firewall geplaatst: Netgate 1100 met pfSense, als router, DHCP-server en firewall
  • De router van de provider in bridge mode gezet
  • DNS over TLS via Quad9 en Cloudflare, zodat de provider geen DNS-verkeer meer ziet
  • Netwerkbrede ad- en malwareblokkering met pfBlockerNG
  • Veilige toegang op afstand met Tailscale
  • Voor mijn ouders: een wachtwoordmanager (NordPass) en MFA
  • Installed my own firewall: a Netgate 1100 running pfSense as router, DHCP server and firewall
  • Put the ISP router in bridge mode
  • DNS over TLS via Quad9 and Cloudflare, so the ISP can no longer see DNS traffic
  • Network-wide ad and malware blocking with pfBlockerNG
  • Secure remote access with Tailscale
  • For my parents: a password manager (NordPass) and MFA
ResultaatResult
Volledige controle over het netwerk, versleuteld DNS-verkeer en sterke, unieke wachtwoorden, zonder dat mijn ouders aan gebruiksgemak inleveren.Full control over the network, encrypted DNS traffic and strong, unique passwords, without my parents losing any ease of use.

Wat niet meteen lukteWhat didn't work right away

Mijn grootsteWhat I leerschool.learned most from.

1Dubbele DHCPDouble DHCP

De wifi-mesh (TP-Link Deco) stond in routermodus en deelde zelf IP-adressen uit. Daardoor liep het DNS-verkeer niet via de firewall en werkte de adblocker niet. Oplossing: de Deco in access-pointmodus, zodat de firewall alles beheert.

The wifi mesh (TP-Link Deco) was in router mode and handed out its own IP addresses. As a result, DNS traffic bypassed the firewall and the ad blocker didn't work. Fix: switched the Deco to access point mode, so the firewall manages everything.

2Geblokkeerde poortenBlocked ports

Een eigen WireGuard-VPN kwam nooit tot stand: de provider blokkeert alle inkomende poorten, ook alternatieven zoals 443. Een Cloudflare Tunnel bestond niet voor de processor van de firewall. Oplossing: Tailscale, dat geen open poorten nodig heeft.

My own WireGuard VPN never connected: the ISP blocks all incoming ports, including alternatives such as 443. Cloudflare Tunnel wasn't available for the firewall's processor. Fix: Tailscale, which doesn't need any open ports.

3Dynamic DNS

De ingebouwde Dynamic DNS-client van pfSense bleef falen. Oplossing: een eigen shellscript dat de Cloudflare API aanspreekt met een API-token met minimale rechten, elke 5 minuten uitgevoerd via een cronjob.

pfSense's built-in Dynamic DNS client kept failing. Fix: my own shell script that calls the Cloudflare API with a least-privilege API token, run every 5 minutes by a cron job.

4HardwaregrenzenHardware limits

Inbraakdetectie met Suricata bleek op termijn te zwaar voor de Netgate 1100, naast de andere diensten. Keuze: Suricata uitgeschakeld; de bescherming loopt via pfBlockerNG en de firewall. Voor volledige IDS/IPS is zwaardere hardware nodig.

Intrusion detection with Suricata turned out to be too heavy for the Netgate 1100 alongside the other services. Decision: disabled Suricata; protection runs through pfBlockerNG and the firewall. Full IDS/IPS needs more powerful hardware.
